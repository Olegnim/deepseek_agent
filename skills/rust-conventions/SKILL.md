# Rust: соглашения

- Форматирование — `cargo fmt`, линт — `cargo clippy -- -D warnings`, сборка —
  `cargo check` (быстро) / `cargo build`, тесты — `cargo test`. После правок
  запускай `cargo check` через `run_shell`: дешёвого «только синтаксис» у Rust нет.
- Ошибки: библиотеки — `Result<T, E>` с `thiserror` (`#[derive(Error)]`),
  приложения — `anyhow`; `?` вместо `unwrap()`/`expect()` в коде, который может
  упасть. `panic!` — только для нарушенных инвариантов.
- Владение: параметры — `&str`/`&[T]`/`&T` вместо `String`/`Vec<T>`/clone;
  `clone()` — осознанно; `Cow<'_, str>` для «иногда владеющий» строк.
- Итераторы и `?` предпочтительнее индексов; не собирай `Vec` из `iter().map()`
  без необходимости — возвращай ленивый итератор.
- `unsafe` — только с комментарием `// SAFETY:` и минимальным блоком.
- Модули: `mod`/`pub(crate)` по умолчанию, публичный API — с `///`-документацией
  и примером; `#[must_use]` там, где игнорирование результата — ошибка.
- Асинхронность: `tokio` по проекту, `async`-функции без блокирующих вызовов
  внутри (`std::fs` → `tokio::fs`), таймауты и отмены — через `select!`/`timeout`.
- Тесты: unit — в `#[cfg(test)] mod tests` рядом с кодом, интеграционные — в
  `tests/`; проверяй и ошибки (`assert!(result.is_err())`).
- Секреты — из окружения (`std::env::var`), не в коде; логи — `tracing`, не
  `println!` в правках.
