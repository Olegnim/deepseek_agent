# Фронтенд: HTML, CSS, JS/TS

## Разметка (HTML)
- Семантика: `header/main/nav/section/article/footer`, а не одни `div`.
- Обязательное доступное имя у изображений (`alt`), у кнопок — текст или `aria-label`.
- Формы: `label` связан с полем (`for`/`id`), у полей есть `name`.
- Валидность: закрытые теги, уникальные `id`, один `h1` на страницу.

## CSS
- Предпочитай CSS-переменные и layout на Flexbox/Grid, а не float/таблицы.
- Адаптивность: mobile-first, `@media`, относительные единицы (`rem`, `%`, `clamp`).
- Не используй `!important` без крайней нужды и инлайн-стили, если есть классы.
- Именование классов — по системе проекта (BEM/utility), не смешивай подходы.

## JS / TS
- `const`/`let`, без `var`. Сравнение — `===`.
- Обработку событий вешай через `addEventListener`, а не `onclick="..."` в разметке.
- DOM-запросы кешируй в переменные, не ищи один элемент в цикле.
- Асинхронность: `async/await`, ошибки — в `try/catch`; не глотай исключения молча.
- TypeScript: не прячь типы через `any`, описывай интерфейсы данных.

## Сеть и данные
- Данные от пользователя не вставляй в DOM через `innerHTML` — только
  `textContent` или безопасная санитация (XSS).
- API-запросы: проверяй `response.ok`, обрабатывай ошибки и состояния загрузки.
- Секреты и токены не держи в клиентском коде.

## Проверка
- Синтаксис JS проверяется автолинтом (`node --check`).
- После правки разметки/стилей перечитай изменённый участок — визуальной
  проверки в браузере у агента нет, поэтому важна аккуратность.
