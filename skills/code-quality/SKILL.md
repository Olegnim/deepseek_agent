# Качество и безопасность правок

- Сначала читай файл (`read_file` / `read_range`), потом меняй.
- Минимальный дифф: правь только то, что нужно для задачи, не переформатируй
  чужие участки и не меняй публичные сигнатуры без необходимости.
- После правки смотри результат автолинта: он запускается автоматически и
  вернёт ошибку синтаксиса, если что-то сломано.
- Не оставляй отладочный код и «временные» заглушки в правках:
  `var_dump`, `print_r`, `console.log`, `print`, `dd`, `debugger`.
- Не ломай существующее поведение: если меняешь публичный API, обнови все вызовы
  (`grep` / `search_code` по имени) и документацию.
- Не удаляй чужой код «на всякий случай» — только по задаче.
- Секреты и ключи не хардкодим: читаем из переменных окружения или конфига.
- Разделяй проверки: синтаксис — быстро, тесты — по необходимости.
- Когда задача выполнена, дай короткое резюме: что изменено и как проверено.
