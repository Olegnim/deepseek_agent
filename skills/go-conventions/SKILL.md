# Go: соглашения

- Форматирование — только `gofmt`/`goimports` (без ручного выравнивания);
  проверка: `go build ./...`, тесты: `go test ./...`, статический анализ —
  `go vet ./...`. Синтаксис одного файла проверяет автолинт (`gofmt -e`).
- Ошибки — значения, не паника: `if err != nil { return fmt.Errorf("...: %w", err) }`;
  оборачивай через `%w`, проверяй `errors.Is/As`. Паника — только для
  «невозможного» и в `main`/`init`.
- Имена: короткие локальные (`ctx`, `req`, `buf`), экспортируемое — с
  комментарием `// Name ...`; акронимы заглавными (`URL`, `ID`, `HTTPClient`).
- Интерфейсы объявляй у потребителя (в пакете, который их использует), маленькие
  (1–3 метода); не возвращай интерфейс без необходимости.
- Контекст: `ctx context.Context` — первый параметр функций с I/O; не храни
  контекст в структурах; всегда `defer cancel()`.
- Горутины: закрывай через `defer`, ограничивай (`errgroup`, `sync.WaitGroup`),
  не оставляй утечек; данные — через каналы или мьютексы, без гонок (`go test -race`).
- Ресурсы — `defer f.Close()` сразу после проверки ошибки; `sql.Rows` закрывай
  после итерации.
- Пакеты: без циклов импортов, никакого `utils`-помойки; `internal/` — для
  приватного кода; тесты — рядом (`foo_test.go`), табличные (`t.Run`).
- Конфигурация — `flag`/`os.Getenv`/`config`-пакет, секреты только из окружения;
  логи — `log/slog` (структурированные), не `fmt.Println` в правках.
