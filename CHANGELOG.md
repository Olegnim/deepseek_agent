## [0.1.0] — 2026-10-12

Первая версия: CLI-агент для работы с кодом через DeepSeek API. Работает в
проекте пользователя (песочница — `PROJECT_ROOT`), определяет стек сам,
подключает навыки и профили, проверяет синтаксис после каждой правки,
делает снапшоты и умеет показывать свою работу прямо в VS Code.

### Добавлено

**Ядро и конфигурация**

- Точка входа `agent.py`: интерактивный REPL и разовые задачи (`-t/--task`).
- `config.py`: `AGENT_HOME` определяется из расположения `agent.py`,
  `PROJECT_ROOT` — из папки запуска (приоритет: `-p` > `DEEPSEEK_PROJECT_ROOT` >
  конфиг в cwd > `agent.config.json` > cwd).
- Слоистые настройки: `<AGENT_HOME>/agent.config.json` → оверрайд
  `<PROJECT_ROOT>/.agent.config.json` (в git не попадает) → `DEFAULTS` в `config.py`.
- Подстановки в JSON: `${env:VAR}`, `${agent_home}`/`${agent_dir}`, `${project_root}`.
- Общие ресурсы (навыки, MCP-конфиги, плагины) ищутся по цепочке
  «проект → папка агента» и объединяются, проектные имеют приоритет.
- Чтение `DEEPSEEK_API_KEY` из переменной окружения и — на Windows — из реестра
  (`setx` начинает работать без перезапуска терминала); резервный вариант —
  `api.api_key` в локальном `.agent.config.json`.
- Ретраи запросов к API (`agent.api_retries`) с экспоненциальной задержкой
  при сетевых ошибках, 429 и 5xx.
- Loop-guard (`agent.loop_guard`): предупреждение, затем остановка при повторе
  одного и того же вызова инструмента с тем же результатом; шаги модели без
  лимита (`agent.max_steps: 0`).
- Статистика токенов и полоса заполнения контекста (`:tokens`, `:context`,
  `--show-tokens`).
- `--doctor` — диагностика окружения без API-ключа: пути, конфиги, навыки,
  MCP-серверы, статус моста VS Code, наличие утилит и пакетов.

**Инструменты агента**

- Файлы: `read_file`, `read_range` (до 500 строк), `write_file`, `edit_file`
  (первое вхождение или `replace_all`, сохранение CRLF/LF), `list_dir`.
- Поиск: `grep` по regex с фильтром по расширениям (или `include="*"`), пропуск
  `node_modules`, `vendor`, `.git` и прочего мусора.
- `run_shell` с таймаутом (`tools.shell_timeout`), рабочей папкой = корень
  проекта и убийством всего дерева процессов при таймауте (POSIX — `killpg`,
  Windows — `taskkill /T`).
- Git только на чтение: `git_status`, `git_diff`, `git_log`.
- Интернет без API-ключей: `web_search` (DuckDuckGo) и `fetch_url`
  (HTML → текст), с SSRF-защитой (локальные и приватные адреса и редиректы
  на них блокируются).
- Все инструменты работают в песочнице проекта: путь вне `PROJECT_ROOT`
  отклоняется; результат инструмента обрезается перед отправкой в контекст.
- Инструменты, неприменимые сейчас (веб выключен, проект не git-репозиторий,
  нет моста VS Code), не показываются модели.

**Автолинт**

- Проверка синтаксиса сразу после `write_file`/`edit_file`, результат
  добавляется к ответу инструмента.
- Правила задаются в конфиге (`lint.rules`) с плейсхолдером `{file}`:
  из коробки `php -l`, `node --check`, `python -m py_compile`, `javac -proc:only`,
  `kotlinc`, `swiftc -parse`.
- Утилиты нет в PATH или правило не задано — проверка молча пропускается;
  отключается ключом `lint.enabled: false`.

**Навыки и профили**

- Навыки — папки с `SKILL.md` (front-matter `name`, `description`,
  `applies_to`) в проекте и рядом с агентом; проектные перекрывают агентские.
- Встроенный набор: `code-quality`, `php-conventions`, `php-web`,
  `python-conventions`, `java-conventions`, `kotlin-conventions`, `android`,
  `swift-conventions`, `ios`, `web-frontend`.
- Отбор навыков по стеку проекта (`applies_to` против тегов из
  `tools/stack.py`); незнакомый стек — fail-open, грузятся все навыки.
- Профили (роли): `php`, `python`, `frontend`, `java`, `kotlin`, `swift` и свои
  из секции `profiles` — флаг `--profile`, команда `:profile`, `--list-profiles`.
- Автоопределение стека по маркерным файлам (`composer.json`, `package.json`,
  `tsconfig.json`, `pyproject.toml`, `go.mod`, `Cargo.toml`, `Gemfile`,
  `pom.xml`/`build.gradle(.kts)`, `AndroidManifest.xml`, `Package.swift`,
  `*.xcodeproj` и др.) с распознаванием популярных фреймворков.
- Дополнительные правила проекта без правки кода агента — `agent.instructions`.

**Безопасность и откат**

- Подтверждение опасных операций (запись файлов, shell, MCP-запись);
  `-y/--yes`/`--no-confirm` и команда `:auto` — для автоматизации.
- Автоснапшот файла перед каждой правкой и команда `:restore`; лимит
  `snapshots.max_backups`.
- Ограничение размера вывода инструментов и shell-команд.

**MCP**

- Подключение внешних MCP-серверов по stdio из `mcp_config.json`/`.mcp.json`
  (формат Claude Desktop), имена инструментов с префиксом сервера
  (`filesystem__read_file`), MCP SDK v1 и v2, подстановки в аргументах.
- Ошибка одного сервера не мешает подключить остальные.

**Интеграция с VS Code (опционально)**

- Расширение-мост `vscode-extension/` (DeepSeek Agent Bridge 0.1.0): локальный
  HTTP-сервер на 127.0.0.1 с токеном, дескриптор — `.agent-cache/vscode-bridge.json`.
- Инструменты `vscode_open`, `vscode_close`, `vscode_close_all`, `vscode_reveal`,
  `vscode_diff`, `vscode_status`; авто-открытие правленого файла без перехвата
  фокуса у терминала.
- Автозапуск редактора на старте сессии (`vscode.auto_start`), команда
  `:vscode start|restart`; во всех сценариях интеграция отказоустойчива —
  нет VS Code, нет расширения или мост не отвечает, агент работает как обычно.

**Кэш и служебные данные**

- `.agent-cache/` в проекте: `backups/` (снапшоты), `logs/` (лог сессии),
  `history.txt` (история ввода); в git не попадает.
- Подсчёт объёма и очистка — `:cache`, `:cache clear`, `--clear-cache`,
  опрос при старте (`cache.ask_on_start`).

**Кроссплатформенность и вывод**

- Windows, Linux, macOS: пути через `pathlib`, кроссплатформенные команды,
  отдельная обработка групп процессов и `python`→`sys.executable` в автолинте.
- Опциональный цветной вывод (`rich`) и ввод с историей и подсветкой
  (`prompt_toolkit`); без них — упрощённый режим.

**Тесты и разработка**

- Набор автотестов `pytest` (`tests/`) — 190 тестов (~5 секунд, без сети и без
  API-ключа): конфигурация и приоритеты, файловые инструменты и границы чтения,
  автолинт, цикл задачи (`_run_loop`) с подменённой моделью, loop-guard, навыки
  и стек проекта, снапшоты и кэш, SSRF-фильтр и разбор выдачи поиска, MCP, мост
  VS Code, shell и git.
- `requirements-dev.txt` (pytest), `pytest.ini`, `CHANGELOG.md`.
- Четыре теста помечены `xfail` и фиксируют известные дефекты (см. ниже), а не
  ошибки прогона.

**Документация**

- README: установка, команды, флаги, навыки и профили, MCP, интеграция с VS Code,
  раздел «Тесты», частые проблемы.
- `vscode-extension/README.md` — установка и сборка расширения-моста.
- `CHANGELOG.md` — этот файл.

### Известные проблемы

- При запуске с `-p` (или когда `PROJECT_ROOT` не совпадает с папкой запуска)
  агент запрашивает модель с уже прочитанными при старте значениями
  `api.model`, `api.temperature`, `api.context_limit`: значения из конфига
  целевого проекта не применяются к запросам (тест
  `tests/test_agent_core.py::test_api_request_uses_model_from_project_config`
  помечен `xfail`).
- `${project_root}` в значениях `agent.config.json` раскрывается в пустую строку
  (первый проход подстановок выполняется без этой переменной), поэтому путь,
  например, в `paths.skills_dir` теряет корень проекта. В `mcp_config.json`
  подстановка работает — она раскрывается отдельно.
- Секция `tools.lint` не действует: `DEFAULTS` всегда содержит секцию `lint`,
  поэтому запасной вариант недостижим — правила автолинта задавайте в `lint`.
- Вывод внешних утилит читается в системной кодировке: на Windows с кодовой
  страницей cp1251 русский текст в `git_diff` превращается в мусор.
- `api.temperature` не влияет на ответы: thinking mode включён по умолчанию и
  не поддерживает `temperature` (параметр молча игнорируется API).
- История диалога растёт без ограничения: при очень длинной сессии возможен
  выход за контекст без предупреждения (в `:context` есть только индикатор).
