### Добавлено

**Мягкое планирование: `PLAN.md` → одно подтверждение → автопилот**

- Режим по умолчанию — `auto`: мелкую задачу агент делает сразу, для крупной
  задаёт один короткий вопрос «планировать или выполнить сразу?».
- Команда `:plan on` включает режим планирования: агент исследует код и пишет
  `PLAN.md` (задачи с `ID`, `depends_on`, наблюдаемым поведением и критерием
  приёмки; тесты — до реализации), правки остальных файлов блокируются
  (`plan_guard` в `execute_tool`, включая MCP-инструменты; `run_shell` разрешён).
- `:plan approve` — единственное подтверждение: план утверждён (`run`),
  подтверждения опасных операций выключаются (автопилот), шаги выполняются по
  порядку `depends_on` без остановок; прогресс отмечается в `PLAN.md` (`- [x] ID`).
- `:plan off` — без планирования и с прежним режимом подтверждений; `:plan auto`
  возвращает решение агенту; `:plan` показывает статус и прогресс
  (`plan_progress` считает чекбоксы).
- В системный промпт добавлен блок «Планирование (мягкий режим)»: мелкие задачи
  выполняются сразу, план — только для нетривиальных.
- Тесты: `tests/test_plan_mode.py`.

### Добавлено

**Выжимка вместо простыней: бюджет вывода инструментов (`tools/digest.py`)**

- Любой результат инструмента больше `tools.output.max_chars` (по умолчанию
  6000 символов) больше не обрезается «в лоб»: в контекст уходит выжимка —
  строки с ошибками (`ERROR`, `FAILED`, `Traceback`, `warning`), начало и конец
  вывода, пометки «сколько строк пропущено».
- Полный вывод сохраняется в `.agent-cache/output/<инструмент>-<время>.txt`
  (хранится `tools.output.keep_files` последних файлов). В выжимке есть путь и
  подсказка читать его точечно (`read_range`, `search_code`).
- Ключевые слова для ранжирования берутся из аргументов вызова, поэтому в
  выжимке `pytest` видно нужные тесты, а в выводе сборки — нужные ошибки.
- Единая точка применения — `execute_tool`: работает и для MCP-инструментов
  (`filesystem__read_file` и т.п.), и как последний предохранитель в цикле
  задачи.
- `run_shell` сжимает большой вывод (pytest, git log, сборка) и сохраняет лог.
- Настройки: `tools.output` (`enabled`, `max_chars`, `head_lines`, `tail_lines`,
  `keep_files`); текущее значение видно в `:config`.
- Тесты: `tests/test_digest.py`.

**Поиск и навигация по коду (`tools/search.py`) — локально, без простыней**

- `search_code(pattern, path, include, context, max_results, fixed,
  ignore_case, files_only)` — regex-поиск с группировкой по файлам, контекстом
  и сводкой («сколько файлов/совпадений, сколько показано»); `fixed=true` —
  поиск подстроки, `files_only=true` — только список файлов.
- `file_outline(path)` — карта символов файла с диапазонами строк: Python через
  `ast`, PHP/JS/TS/Java/Kotlin/Swift/Go/Ruby/Rust/CSS — регулярками; для папки
  отдаёт карту её файлов. Модель больше не читает файл целиком, чтобы найти
  одну функцию.
- `read_symbol(name, path)` — тело символа по имени (по отступу для Python, по
  балансу скобок для остальных языков), с обрезкой длинных тел и поиском по
  проекту (если определение встречается в нескольких файлах — просит уточнить).
- `diff_files(a, b, context, max_lines)` — unified diff двух файлов: только
  изменения, статистика `+N / -M`.
- `find_files(pattern, path, max_results)` — файлы по glob-маске с пропуском
  `node_modules`/`vendor`/`build`.
- `project_map(depth, max_entries)` — структура проекта с лимитами.
- Общий обход файлов вынесен в `filesystem.iter_files` (его же использует
  `grep`), поэтому фильтры и пропуск каталогов одинаковые у всех инструментов.
- Настройки: `tools.search` (`max_results`, `context`, `max_files`).
- Тесты: `tests/test_search.py`.

**Веб: фрагменты по запросу вместо начала страницы**

- `fetch_url(url, query="...")` — если задан вопрос, возвращаются абзацы, где
  встречаются ключевые слова (`tools.web.excerpt_paragraphs`), а не первые
  символы страницы; полный текст сохраняется в `.agent-cache/output`.
- Длинная страница без `query` отдаётся началом в пределах бюджета
  (`tools.output.max_chars`) с подсказкой повторить запрос через `query=...`,
  а не обрезкой «в лоб».

**Промпт и конфиг**

- В системный промпт добавлен блок «Экономия контекста»: как искать
  (`search_code`, `file_outline`, `read_symbol`, `diff_files`, `find_files`),
  где лежит полный вывод и почему shell-команды стоит делать «тихими».
- `agent.config.json`: секции `tools.output` и `tools.search`, параметр
  `tools.web.excerpt_paragraphs`.

**Стриминг ответа (stream)**

- `api.stream` (по умолчанию `false` — ждать ответ целиком): при `true` ответ
  запрашивается с `stream=true` и `stream_options={"include_usage": true}`,
  поэтому текст и рассуждения видны по мере генерации, а не после полного
  ответа. По умолчанию оставлен блокирующий режим: только в нём работает
  анимация «DeepSeek думает» и markdown-форматирование ответа в терминале.
- Чанки склеиваются в обычный ответ: `content` и `reasoning_content`
  конкатенируются, `tool_calls` собираются по `index` (имя приходит первым
  чанком, аргументы — кусками), `usage` берётся из финального чанка. Разбор в
  `_run_loop` общий для обоих режимов.
- Рассуждения печатаются приглушённым курсивом по ходу генерации, ответ —
  сразу после них; повторно текст не выводится.
- Переключение на лету — команда `:stream [on|off|auto]`, текущий режим виден в
  `:config` и `:stream`.
- История диалога теперь хранит сообщение ассистента как `dict`
  (`_assistant_message`), а не pydantic-объект SDK: одинаково работает для
  стриминга и обычного ответа.
- Тесты: сборка ответа из чанков (текст, рассуждения, `tool_calls`),
  `:stream`, разбор `api.stream` (`tests/test_api_features.py`).

**Возможности DeepSeek API: thinking mode, лимит ответа, vision**

- Thinking mode: секция `api` в конфиге — `thinking` (вкл/выкл) и
  `reasoning_effort` (`low` / `high` / `max`, `none` выключает рассуждения;
  алиасы API `minimal`, `medium`, `xhigh`, `ultra` понимаются). Параметры
  уходят в `extra_body` (`{"thinking": {"type": …}}` + `reasoning_effort`),
  поэтому работают с любой версией `openai>=1.40`. Переключение на лету —
  команда `:think [on|off|low|high|max|auto]`; текущий режим виден в
  приветствии, `:config`, `:doctor` и системном промпте.
- `api.max_tokens` (0 = значение API по умолчанию, максимум 384K) и `api.top_p`
  (0 = не передавать) — раньше запрос шёл вообще без лимита ответа.
- `finish_reason` теперь разбирается: при `length` агент подсказывает увеличить
  `api.max_tokens`, при `insufficient_system_resource`/`aborted` предупреждает.
- Статистика сессии (`:tokens`) учитывает `completion_tokens_details.reasoning_tokens`
  — видно, сколько токенов ушло на рассуждения.
- Vision (`tools/vision.py`): новый инструмент `read_image` отправляет модели
  изображение (JPEG, PNG, GIF, WebP — формат по содержимому файла) как
  `image_url` с base64 data URL. Картинка кладётся в отдельное `user`-сообщение
  после ответов инструментов: по документации изображения в system/assistant
  сообщениях отклоняются с 400. Настройки — секция `vision` (`enabled`,
  `max_bytes`, `detail` = `low`/`high`/`original`/`auto`).
- `read_file` на изображении больше не отдаёт бинарный мусор: подсказывает
  модели вызвать `read_image`.
- Тесты: `tests/test_api_features.py` (проводка параметров запроса, `:think`,
  лимиты, `read_image`, передача картинки в диалог).

**MCP: разрешённые папки через roots/list**

- Агент объявляет MCP-серверам capability `roots` (`ClientSession(list_roots_callback=…)`)
  и отдаёт им список разрешённых папок как `file://`-URI. Из-за отсутствия этой
  возможности сервер `@modelcontextprotocol/server-filesystem` вместо опроса корней
  писал в stderr `Client does not support MCP Roots, using allowed directories set
  from server args`.
- Список корней: секция `mcp.roots` в `agent.config.json` (по умолчанию — корень
  проекта) плюс папки, переданные конкретному серверу в `args` — так переход на
  roots не сужает доступ. Несуществующие пути отбрасываются, и если валидных папок
  нет, capability не объявляется (сервер продолжает работать по аргументам).
- Пути нормализуются `Path.resolve()`, URI собираются `Path.as_uri()`: одинаково
  на macOS (`/tmp` → `/private/tmp`), Linux и Windows (`file:///C:/…`).
- В `:config`/`--doctor` добавлена строка `mcp_roots:`; README — раздел
  «Разрешённые папки (roots/list)».

### Исправлено

**`grep`/`find_files`/`list_dir` и путь к файлу**

- `grep(pattern, path="CHANGELOG.md")` отвечал `ERROR: папка не найдена`, хотя
  `search_code` с файлом работал. Теперь `path` у `grep` — папка **или** один файл
  (для файла `include` игнорируется), а в тексте ошибки — «путь не найден».
- `find_files` с путём к файлу возвращает этот файл, а `list_dir` объясняет, что
  передан файл, а не папка.
- Тесты: `tests/test_filesystem.py`, `tests/test_search.py`.

**Кириллица в выводе `run_shell` (поиск по проекту через терминал)**

- `run_shell` читал вывод с кодировкой локали (`text=True`), поэтому UTF-8 вывод
  `git grep`, `node`, `python` превращался в «РЎРѕРІРїР°РґРµРЅРёР№…». Теперь вывод
  читается байтами и декодируется `_decode`: строгий UTF-8, иначе — лучший из
  кандидатов (`cp866` для встроенных команд cmd.exe, `cp1251`, локаль) по
  «похожести на русский».
- Подсказка модели про Windows больше не советует `findstr` для поиска по
  проекту: на UTF-8 файлах с русским текстом он молча возвращает пустой
  результат. Вместо этого — встроенные `grep`/`search_code`/`find_files`, а в
  терминале — `git grep`.
- Тесты: `tests/test_shell_git.py` (`_decode` для UTF-8/cp866/cp1251 и вывод
  дочернего процесса в UTF-8).

**Строка статуса под ответом (контекст и токены)**

- `ui_status` печатал строку через `Text(...)`, а он не разбирает Rich-разметку:
  в консоль попадали литералы `[green]░░…[/green]` и `[bold]сессия:[/bold]`.
  Теперь используется `Text.from_markup` (при ошибке разметки — безопасный
  откат к тексту без тегов).
- Бар контекста больше не выглядит пустым на малых значениях: при 4%
  `int(4/5)` давал 0 закрашенных блоков — теперь минимум один.
- Статистика разбита на две строки (сессия / кэш и рассуждения): одна строка
  ~110 символов переносилась посреди значения («… / 23 881» + «miss»).
- Тесты: `tests/test_agent_core.py` (разметка статуса и бар при 4%).

### Исправлено

**Python-интерпретатор и кроссплатформенность (macOS / Linux / Windows 11)**

- Автолинт, подсказки модели и `--doctor` больше не зависят от того, есть ли в
  PATH команда `python`: везде используется интерпретатор самого агента
  (`config.python_exe()` → `sys.executable`). `py -3 …` (launcher Windows) тоже
  понимается — служебный флаг отбрасывается.
- Примеры команд в системном промпте (`run_shell("python -m py_compile …")`)
  заменены на реальные для этой ОС: раньше на macOS/Linux подсказка не работала.
- `--doctor`: показываются `py` в списке утилит, интерпретатор агента и состояние
  `pytest` (dev-зависимость) с актуальной командой установки.
- Байткод автолинта (`py_compile`) больше не создаёт `__pycache__` в проекте
  пользователя: `PYTHONPYCACHEPREFIX` указывает на системный временный каталог.
- Вывод линтера и `code --list-extensions` читается с `errors="replace"` — на
  Windows с кодовой страницей cp866/cp1251 больше нет падений на декодировании.
- `.vscode/tasks.json`: добавлена задача `DeepSeek: tests (pytest)`; в комментарии
  описано, как использовать `py`-launcher.

**Кроссплатформенные детали запуска и путей (Windows / macOS / Linux)**

- Команда разбирается на «программу» и «остаток» с учётом кавычек
  (`config.split_command`): правило автолинта и подсказка вида
  `"C:/Program Files/Python/python.exe" -m py_compile {file}` больше не
  считаются отсутствующей утилитой (`tools/linter.py`) и не превращаются
  в мусор при подстановке интерпретатора агента.
- MCP-серверы с `command: "npx"` снова подключаются в Windows: команда
  ищется в PATH (там это `npx.cmd`, который SDK без shell не находит),
  а `.cmd`/`.bat` запускаются через `cmd /c` (`resolve_server_command`).
- Путь из ответа модели доводится до фактического имени файла: на macOS имена
  хранятся в NFD, а Windows/macOS не различают регистр (`agent.safe_path`
  → `_match_existing`). Раньше такой путь молча давал «файл не найден».
- `vscode-extension/selftest.js` больше не требует команды `python`: на
  macOS/Linux берётся `python3`, переопределение — `DEEPSEEK_AGENT_PYTHON`;
  если интерпретатор не запустился, выводится понятное сообщение.
- `.gitattributes`: в репозитории LF (`* text=auto eol=lf`), а `*.bat`/`*.cmd`/
  `*.ps1` — CRLF, поэтому правки из Windows не дают дифф «изменился весь файл».
- `--doctor`: в списке утилит появился `git`; README — в «Частых проблемах»
  добавлены строки про регистр/Unicode в именах файлов и про `npx.cmd`.
- В системный промпт добавлен раздел «Оболочка»: на Windows команды идут через
  `cmd.exe` (`set VAR=… && …`, нет `export`, нет `;`, нет POSIX-утилит),
  на Linux/macOS — через `/bin/sh`. Раньше модель могла выдать команду,
  работающую только в другой ОС, и это выглядело как сбой агента.
- README: для Ubuntu 24.04+/Debian 12+ описан PEP 668
  (`error: externally-managed-environment`) — установка через venv, разовое
  исключение `--break-system-packages`; то же добавлено в «Частые проблемы».
- README: подсказка про лимит 260 символов в Windows — снапшоты повторяют
  структуру проекта в `.agent-cache/backups/`, поэтому при длинных путях
  помогает `core.longpaths`/`LongPathsEnabled` или вынос `paths.backup_dir`
  из проекта (`${env:TEMP}/deepseek-agent-backups`).

**Известные дефекты 0.1.0 (закрыты, `xfail`-маркеры в тестах сняты)**

- Настройки `api.*` из конфига целевого проекта применяются к запросам и при
  запуске с `-p`: `agent._api_request` и индикатор контекста читают значения из
  `config` в момент вызова, а не из констант, загруженных при импорте.
- `${project_root}` в `agent.config.json` раскрывается: на первом проходе
  подстановка сохраняется (`expand_vars(..., keep=...)`) и заменяется на втором,
  когда корень проекта уже известен.
- Секция `tools.lint` снова действует как устаревший вариант `lint`: явные
  секции берутся из прочитанных файлов конфигов, а не из `DEFAULTS`.
- `git_diff`/`git_status`/`git_log` читают вывод git как UTF-8 независимо от
  кодовой страницы консоли, а «не git-репозиторий» распознаётся и на русской
  локали (раньше — только по английской строке).

## [0.1.0] — 2026-10-12

Первая версия: CLI-агент для работы с кодом через DeepSeek API. Работает в
проекте пользователя (песочница — `PROJECT_ROOT`), определяет стек сам,
подключает навыки и профили, проверяет синтаксис после каждой правки,
делает снапшоты и умеет показывать свою работу прямо в VS Code.

### Добавлено

**Ядро и конфигурация**

- Точка входа `agent.py`: интерактивный REPL и разовые задачи (`-t/--task`).
- `config.py`: `AGENT_HOME` определяется из расположения `agent.py`,
  `PROJECT_ROOT` — из папки запуска (приоритет: `-p` > `DEEPSEEK_PROJECT_ROOT` >
  конфиг в cwd > `agent.config.json` > cwd).
- Слоистые настройки: `<AGENT_HOME>/agent.config.json` → оверрайд
  `<PROJECT_ROOT>/.agent.config.json` (в git не попадает) → `DEFAULTS` в `config.py`.
- Подстановки в JSON: `${env:VAR}`, `${agent_home}`/`${agent_dir}`, `${project_root}`.
- Общие ресурсы (навыки, MCP-конфиги, плагины) ищутся по цепочке
  «проект → папка агента» и объединяются, проектные имеют приоритет.
- Чтение `DEEPSEEK_API_KEY` из переменной окружения и — на Windows — из реестра
  (`setx` начинает работать без перезапуска терминала); резервный вариант —
  `api.api_key` в локальном `.agent.config.json`.
- Ретраи запросов к API (`agent.api_retries`) с экспоненциальной задержкой
  при сетевых ошибках, 429 и 5xx.
- Loop-guard (`agent.loop_guard`): предупреждение, затем остановка при повторе
  одного и того же вызова инструмента с тем же результатом; шаги модели без
  лимита (`agent.max_steps: 0`).
- Статистика токенов и полоса заполнения контекста (`:tokens`, `:context`,
  `--show-tokens`).
- `--doctor` — диагностика окружения без API-ключа: пути, конфиги, навыки,
  MCP-серверы, статус моста VS Code, наличие утилит и пакетов.

**Инструменты агента**

- Файлы: `read_file`, `read_range` (до 500 строк), `write_file`, `edit_file`
  (первое вхождение или `replace_all`, сохранение CRLF/LF), `list_dir`.
- Поиск: `grep` по regex с фильтром по расширениям (или `include="*"`), пропуск
  `node_modules`, `vendor`, `.git` и прочего мусора.
- `run_shell` с таймаутом (`tools.shell_timeout`), рабочей папкой = корень
  проекта и убийством всего дерева процессов при таймауте (POSIX — `killpg`,
  Windows — `taskkill /T`).
- Git только на чтение: `git_status`, `git_diff`, `git_log`.
- Интернет без API-ключей: `web_search` (DuckDuckGo) и `fetch_url`
  (HTML → текст), с SSRF-защитой (локальные и приватные адреса и редиректы
  на них блокируются).
- Все инструменты работают в песочнице проекта: путь вне `PROJECT_ROOT`
  отклоняется; результат инструмента обрезается перед отправкой в контекст.
- Инструменты, неприменимые сейчас (веб выключен, проект не git-репозиторий,
  нет моста VS Code), не показываются модели.

**Автолинт**

- Проверка синтаксиса сразу после `write_file`/`edit_file`, результат
  добавляется к ответу инструмента.
- Правила задаются в конфиге (`lint.rules`) с плейсхолдером `{file}`:
  из коробки `php -l`, `node --check`, `python -m py_compile`, `javac -proc:only`,
  `kotlinc`, `swiftc -parse`.
- Утилиты нет в PATH или правило не задано — проверка молча пропускается;
  отключается ключом `lint.enabled: false`.

**Навыки и профили**

  `applies_to`) в проекте и рядом с агентом; проектные перекрывают агентские.

### Известные проблемы

- При запуске с `-p` (или когда `PROJECT_ROOT` не совпадает с папкой запуска)
  агент запрашивает модель с уже прочитанными при старте значениями
  `api.model`, `api.temperature`, `api.context_limit`: значения из конфига
  целевого проекта не применяются к запросам (тест
  `tests/test_agent_core.py::test_api_request_uses_model_from_project_config`
  помечен `xfail`).
- `${project_root}` в значениях `agent.config.json` раскрывается в пустую строку
  (первый проход подстановок выполняется без этой переменной), поэтому путь,
  например, в `paths.skills_dir` теряет корень проекта. В `mcp_config.json`
  подстановка работает — она раскрывается отдельно.
- Секция `tools.lint` не действует: `DEFAULTS` всегда содержит секцию `lint`,
  поэтому запасной вариант недостижим — правила автолинта задавайте в `lint`.
- Вывод внешних утилит читается в системной кодировке: на Windows с кодовой
  страницей cp1251 русский текст в `git_diff` превращается в мусор.
- `api.temperature` не влияет на ответы: thinking mode включён по умолчанию и
  не поддерживает `temperature` (параметр молча игнорируется API).
- История диалога растёт без ограничения: при очень длинной сессии возможен
  выход за контекст без предупреждения (в `:context` есть только индикатор).

> Первые четыре пункта этого списка (настройки `api.*` при `-p`, `${project_root}`
> в конфиге, неработающий `tools.lint`, кодировка вывода git) исправлены в
> `Unreleased` — соответствующие тесты больше не помечены `xfail`.
