# Интеграции: MCP и VS Code

## MCP-серверы

Создайте `mcp_config.json` в корне проекта или рядом с агентом (ищутся и
объединяются автоматически):

```json
{
  "mcpServers": {
    "filesystem": {
      "enabled": true,
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "${project_root}"]
    }
  }
}
```

- Абсолютные пути не нужны — используйте `${project_root}` (`${agent_dir}` и
  `${env:VAR}` тоже доступны).
- `npx` требует Node.js, `uvx` — `uv`. Первый запуск может занять 10–30 секунд.
- Сервер с `"enabled": false` пропускается. Статус — по `:mcp`.
- MCP-инструменты, меняющие файлы/выполняющие команды, проходят через
  подтверждение (отключается `--yes`).
- Инструменты сервера видны модели с префиксом `сервер__инструмент`.

### Разрешённые папки (roots/list)

Агент объявляет серверам разрешённые папки сам — протоколом MCP roots, а не только
аргументами команды:

- по умолчанию это корень проекта (`paths.project_root`);
- папки из `args` сервера добавляются автоматически, поэтому доступ не сужается;
- список можно расширить секцией `mcp.roots` в `agent.config.json` (относительные
  пути — от корня проекта, `${project_root}` работает):

```json
{ "mcp": { "roots": ["${project_root}", "~/shared"] } }
```

Если сервер пишет в stderr `Client does not support MCP Roots, using allowed
directories set from server args` — значит клиент не объявил capability `roots`;
агент объявляет её, как только есть хотя бы одна существующая папка. Посмотреть,
что объявлено, можно командой `:config` (строка `mcp_roots:`) или инструментом
`filesystem__list_allowed_directories`.

## VS Code

### Мост: агент открывает файлы в редакторе

Расширение из `vscode-extension/` поднимает в VS Code локальный HTTP-мост на
`127.0.0.1` и пишет порт с токеном в `.agent-cache/vscode-bridge.json`. Пока он
жив, агент открывает правленые файлы в новых вкладках, показывает их в проводнике
и открывает дифф со снапшотом — работа агента видна прямо в редакторе.

Интеграция **необязательная и отказоустойчивая**: если VS Code не запущен,
расширение не установлено, файл-дескриптор битый или мост не отвечает —
инструменты `vscode_*` просто не показываются модели, авто-открытие пропускается,
агент работает как обычно. Никаких исключений и зависаний; принудительно
выключается через `"vscode": { "enabled": false }`.

**Запуск — три шага:**

1. **Установите расширение** (один раз). Проще всего — папкой расширений, без
   сборки и Node.js:

   ```powershell
   # Windows (PowerShell) — junction на папку vscode-extension
   New-Item -ItemType Junction -Path "$env:USERPROFILE\.vscode\extensions\deepseek-agent-bridge" -Target "<AGENT_HOME>\vscode-extension"
   ```

   ```bash
   # Linux / macOS — симлинк
   ln -s "<AGENT_HOME>/vscode-extension" ~/.vscode/extensions/deepseek-agent-bridge
   ```

   Другие варианты (VSIX через `npx @vscode/vsce`, отладка через F5) — в
   [`../vscode-extension/README.md`](../vscode-extension/README.md).

2. **Откройте проект в VS Code**: `code <PROJECT_ROOT>` (или **File → Open
   Folder**). В статус-баре появится индикатор `DeepSeek: мост`.

3. **Запустите агента.** Если VS Code уже открыт с проектом, ничего делать не
   нужно — мост найдётся сам, а в шапке агента будет строка
   `VS Code: мост активен (127.0.0.1:…)`.

### Автозапуск (агент поднимает редактор сам)

При старте интерактивного режима агент проверяет мост и, если его нет, сам
запускает VS Code с проектом (CLI `code` из PATH) и ждёт мост до `vscode.start_wait`
секунд. Нет `code` в PATH или расширение не установлено — будет короткая подсказка,
агент продолжит как обычно. Для разовых задач (`-t "…"`) автозапуск не выполняется,
чтобы не открывать редактор в скриптах.

- запустить/перезапустить вручную: `:vscode start` (`:vscode restart` — даже если
  мост уже активен);
- проверить состояние: `:vscode` или `python agent.py --doctor` (блок **VS Code**);
- выключить автозапуск: `"vscode": { "auto_start": false }`.

### Настройки

| Ключ | По умолчанию | Описание |
|---|---|---|
| `enabled` | `true` | `false` — инструменты `vscode_*` не показываются модели. |
| `auto_open` | `true` | Открывать файл после `write_file` / `edit_file`. |
| `auto_close_previous` | `false` | Перед открытием нового файла закрывать предыдущую вкладку агента. |
| `timeout` | `5` | Таймаут HTTP-запроса к мосту, секунды. |
| `auto_start` | `true` | На старте самому запускать VS Code, если моста нет. |
| `start_wait` | `8` | Сколько секунд ждать мост после запуска VS Code. |

### Запуск агента задачами VS Code

`.vscode/tasks.json` из репозитория уже готов (команда `python`/`python3`
выбирается по ОС): откройте папку **своего проекта** в VS Code и запустите задачу
через **Ctrl+Shift+P → `Tasks: Run Task` → `DeepSeek: …`**. Терминал VS Code
стартует в корне проекта, поэтому `-p` не нужен. Задача `DeepSeek: tests (pytest)`
запускает `pytest` в папке агента.

Если `tasks.json` лежит в другом проекте — используйте в нём
`${env:DEEPSEEK_AGENT_HOME}/agent.py` и задайте переменную с путём к папке агента
(`setx DEEPSEEK_AGENT_HOME "..."` / `export DEEPSEEK_AGENT_HOME="..."`).
